任务：对指定范围的代码做死代码和无用注释的排查，只出报告，不修改任何文件。

【排查范围】
范围：<这里填写目录、模块或文件名；不填则为整个工程源码>
始终排除：第三方库目录、构建输出目录、自动生成的文件（如 moc_、ui_、qrc_ 开头的文件）。
注意：判断"是否被使用"时，搜索范围必须是整个工程源码，不能只在排查范围内搜索。

【最重要的规则】
1. 全程只读。不许修改、新增、删除、格式化任何文件。
2. 如果为了验证而临时改了文件，验证完必须立即还原。报告最后附 git status 输出，证明工作区干净。
3. 不许修复、不许优化、不许重构、不许顺手整理，发现的其他问题只在报告里列出。
4. 每一条结论必须附证据：搜索关键字、搜索范围、命中的文件和行号。没有证据的结论不许写。无法确定的写"无法确定"加原因，不许猜测，不许凭命名或印象判断。

【第一部分：死代码检查项】
1. 函数和成员函数：是否有调用点。
2. 成员变量和全局变量：是否被读取。只被声明、只被赋值、只被写入而从未读取，都算"未被读取"，单独标注是哪一种。
3. 信号：是否被 emit，是否被 connect。两者分开判断：只声明没有 emit 属于死信号；有 emit 没人 connect 属于无人接收；有 connect 没有 emit 属于永远收不到。
4. 槽函数和 lambda：是否被连接或调用。
5. 类、结构体、枚举及枚举值、typedef 和 using 别名、宏定义：是否被引用。
6. #include：本文件内是否有对应符号被使用。
7. 永远不会执行的分支（条件恒真或恒假、return 之后的代码）。
8. 被注释掉的代码块。
9. 整个文件：没有被任何文件 include，也没有登记在构建文件中。
10. 配置键、资源文件条目、图标和样式表中的 objectName 或属性选择器：是否有代码引用。只列出，不要判定为可删。

【以下情况不许判为死代码，必须归入"需人工确认"并说明原因】
- 虚函数的重写、事件处理函数（如 keyPressEvent、paintEvent、eventFilter、closeEvent）、被基类或框架回调的函数。
- 通过字符串连接的信号槽（SIGNAL()、SLOT() 宏）、Q_INVOKABLE、Q_PROPERTY 的读写函数、QML 暴露的接口、元对象系统反射调用。
- 被 qss 样式表通过 objectName 或属性引用的控件名。
- 通过字符串拼接或配置动态引用的内容（配置键、资源路径、图标名）。
- 公开的接口或被插件、外部程序使用的接口。
- 被模板、宏展开后才使用的符号。
- 在头文件里的 #include：可能被其他文件间接依赖。必须确认删除后所有 include 该头文件的文件仍能编译，有间接依赖的标注"有间接依赖，不可删"。
- 平台条件编译（#ifdef）包住的代码：只在其他平台生效的代码，不能因为当前平台没用到就判为死代码。

【第二部分：注释分类】
范围内每条注释归入一类，列出文件、行号、原文：
A 类（必须保留）：说明设计意图、约束、原因、注意事项、历史教训的注释。判断标准：删掉后，后来的人无法从代码本身看出"为什么这样做"。含"铁律""必须""禁止""隔离""不与……共用""兜底""只……不……""注意"等约束性表述的一律归 A。
B 类（建议删除）：只是复述下一行代码在做什么的注释；对应功能已被删除的过期注释；被注释掉的旧代码；内容与现有代码明显不符的注释。每条说明判定原因。
C 类（不确定）：无法判断是否承载设计意图的注释。分隔线类注释（如 "// ====="）单独列在 C 类。
注意：以 emoji 开头的注释不能仅凭 emoji 判定为装饰，必须看内容；说明"为什么"的注释，哪怕写得啰嗦也归 A。

【第三部分：观察项（不是死代码，只如实记录，不给修复建议）】
- 对象创建后一直隐藏或没有加入任何布局，但仍有代码在往里写内容。
- 同一个状态在两处各保存了一份。
- 同一条规则在两处重复书写。
- 声明了但没有定义的函数，或定义了但头文件里没声明的函数。

【报告格式】
1. 汇总：各类问题的数量。
2. 死代码表：文件 | 行号 | 内容 | 类型 | 判定（确认未使用 / 无法确定 / 需人工确认 / 有间接依赖不可删）| 证据。
3. 注释表：A、B、C 三类分别列出。
4. 观察项。
5. 工作区状态：git status 的输出。
6. 超出范围、没有写进报告的问题，一句话列出即可。
