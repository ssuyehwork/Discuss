## 0.2 双轨隔离
应用分为"SQLite 内存模式"和"磁盘目录模式"两种。两者运行时各自独立，相互不干扰、井水不犯油水，不共享判断逻辑、不共享数据加载路径。

# 1. 关于“分类”与“快速访问”的关联

## 1.1 概念与绑定机制
在侧边栏分类树中，“分类”（User Category，原称“我的分类”）与“快速访问”（Quick Access / Favorite Group）本质上共享同一套底层的物理分类表 `categories`。
其中，“分类”是基于 parentId 继承链构建的树状分层结构。而“快速访问”则是一组扁平、置顶的镜像代理节点容器。

## 1.2 置顶关联数据模型
每个物理分类在底层数据表 `categories` 中都有一个布尔值属性 `pinned`，代表该分类的置顶状态。
在模型构建 (CategoryModel) 中：
- 渲染“分类”根分组节点，并在该节点名右侧显示当前手动和自动创建的分类数量（即排除了顶级托管库本身之后的所有自定义分类总数）。其下递归挂载所有用户自定义分类。物理分类节点的 `PinnedRole` 绑定其对应的 `pinned` 属性。
- 渲染“快速访问”分组节点时：系统会遍历所有类别。只要分类的 `pinned` 属性为 `true`（或 1），系统就会在此分组节点下创建一个全新的 **镜像代理节点（Mirror Item）**。
- 该镜像代理节点底层绑定相同的物理 `IdRole`（同为 `cat.id`）、`TypeRole` 等属性，实现高强度的关联 and 逻辑复用。

## 1.3 交互联动生命周期
在 UI 层 (CategoryPanel)，右键单击某个具体分类时：
- 若未置顶，右键菜单显示 “添加至‘快速访问’”。点击后将对应分类的 `cat.pinned` 改为 `true`，通过 `CategoryRepo::update(cat)` 持久化落盘并刷新模型。
- 若已置顶，右键菜单显示 “从‘快速访问’中移除”。点击后将对应分类的 `cat.pinned` 改为 `false`，通过 `CategoryRepo::update(cat)` 持久化落盘并刷新模型。
- 不管是从正常自定义树还是置顶列表中点击同一 ID 的节点，两边最终都分发相同的 ID 给逻辑处理模块，保证无缝穿透、完全联动。

## 1.4 “分类”外壳容器与交互恢复规则
- **节点层级构建**：分类树重新引入带有 `NameRole = "分类"` 的顶级容器节点。所有顶级自定义分类（`parentId == 0` 且名称不以 `ArcMeta.Library_` 开头）均挂载在此容器节点下。
- **计数显示规则**：“分类”容器节点名称显示为 `"分类 (%1)"`，其中 `%1` 计的是**所有手动和自动创建的分类数量**（即排除了顶级托管库本身之后，剩下所有的手动和自动创建分类的总个数）。
- **空白处或根容器拖放**：当用户将项目或分类拖拽至树视图空白区域或“分类”根容器上时，其在数据库中对应的物理分类 `parentId` 必须归零（`parentId = 0`），以此物理对齐顶级自定义分类的定位。
- **拖放与物理同步阻断**：遍历分类树进行 parentId 与 sortOrder 的物理同步时，只有进入“分类”子树内部的自定义分类节点才触发数据库 parentId 关系更新。而“快速访问”镜像子树内的任何位置改变均不回写 parentId 继承关系，从而保证数据流单向纯净。
