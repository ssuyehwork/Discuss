## 一、 核心设计理念与三条铁律

```
                【 QuarkMeta 核心设计哲学 】
    ┌──────────────────────────────────────────────────┐
    │  1. 纯磁盘直连轻量化（免管理员权限、零常驻全盘内存）│
    │  2. 双核中央神经调度（指令统一由大脑出，广播由传声筒发）│
    │  3. 物理 File ID 唯一缓存（改名移动不丢图，两端无缝共享）│
    │  4. 单次 I/O 极速提图（一次读盘，全量产出尺寸、高清图、色值）│
    └──────────────────────────────────────────────────┘
```

### 必须坚守的“三条交互铁律”
1. **铁律一（UI 禁调底层）**：所有 UI 视图层代码**严禁直接调用** `MetadataManager`、`DatabaseManager`、`DiskIoService` 等底层接口。
2. **铁律二（UI 只能发 Command）**：UI 上的所有用户操作（打星、设色、增删标签、重命名、删除）必须封装为 `AppCommand` 投递给 `CoreEngine`。
3. **铁律三（UI 只能听 Event 局部刷）**：UI 严禁无脑全量刷全屏，必须监听 `CentralEventHub` 广播的强类型 `AppEvent` 进行像素级局部增量重绘。

## 三、 核心关键业务流施工标准

### 1. 缩略图极速提图与 File ID 跨模式共享流

```text
[ 视口滚动探测 ] 
       │
       ▼ (拉取当前屏可见的 30 张卡片)
[ DiskItemModel 并行任务池 ]
       │ (多线程并发，根据 CPU 核心数启动 8~16 线程)
       ▼
[ 1. 查缓存 (0ms) ] ──> 命中缓存文件: .QuarkMeta/disk_thumbs/<卷ID>/<前2位>/<FileID>.jpg ──> 直接返回显示！
       │ (未命中时)
       ▼
[ 2. 物理读盘 (仅读 1 次) ] ──> ImageDecoderFacade::decodeSinglePass(filePath, 512)
       ├──> 获得原始物理尺寸 (Width x Height) ──> 回填内存模型
       └──> 获得 512x512 高清 QImage (标准 Windows 句柄提取 File ID，免管理员权限)
                 │
                 ├──> [落盘] 写入 JPEG (Quality 85) 缩略图池 (<1ms)
                 └──> [提色] 内存 64x64 切片 + Gamma LUT 提取主色与调色盘 (<0.5ms)
```

- **同盘改名/移动**：File ID 不变 $\rightarrow$ 缩略图 **0 毫秒永久命中，免重复生成**；
- **内存模式与磁盘模式**：指向同一套 File ID 路径 $\rightarrow$ **100% 共享共用，磁盘占用减半**。

---

### 2. 交互指令与局部更新流（三条铁律闭环）

```text
[ 用户在 UI 上打星/改色/删文件 ]
       │
       ▼ (1. 封装命令，禁止直调底层)
CoreEngine::instance().executeCommand(AppCommand{ Type::SetRating, targetPaths, params })
       │
       ▼ (2. 大脑校验并调度后台 Service 写入数据)
MetadataManager / SQLite / DiskIoService
       │
       ▼ (3. 写入成功后提交事件)
CentralEventHub::instance().publishEvent(AppEvent{ Type::MetadataUpdated, targetPath, payload })
       │
       ▼ (4. 传声筒去重、削峰并安全广播)
[ UI 订阅者收到事件，仅重绘 targetPath 这一张卡片，禁止刷全屏！ ]
```

---

### 3. 系统停机与秒退熔断时序（解决后台卡死）

```text
[ 用户点击“退出程序” ]
       │
       ▼
[ 第 1 步：熔断生产端 (Cut Producers) ]
CoreController::requestShutdown();
MediaExtractorPipeline::instance().cancelAll();  <--- 原子设置中断位，子线程瞬间退出
       │
       ▼
[ 第 2 步：线程池排空 (Drain ThreadPool) ]
QThreadPool::globalInstance()->waitForDone(200); <--- 限制 200ms 超时，严禁无限期死等
       │
       ▼
[ 第 3 步：数据库单线程安全落盘与闭卷 (Flush & Close DB) ]
DatabaseManager::instance().shutdown();          <--- 唯一落盘入口，释放 SQLite 句柄
       │
       ▼
[ 0.1 秒内干净退出，绝不残留后台进程 ]
```

## 四、 架构收益指标对照

| 维度 | 旧架构状态（已废弃） | 新架构标准（本蓝图） |
| :--- | :--- | :--- |
| **模块通信** | 网状乱牵线、UI 直接裸调数据库 | **双核中枢调度，三条铁律严格隔离** |
| **单图处理耗时** | 50ms ~ 150ms（多次读盘 + PNG 压缩） | **2ms ~ 4ms（单次 I/O + JPEG 85 + 内存 LUT）** |
| **大目录加载（3000+文件）** | 单线程串行排队、界面卡死假死 | **QThreadPool 视口多核并行，秒级推流** |
| **同盘移动/改名** | 路径哈希失效，缩略图全部重新生成 | **物理 File ID 锁定，0 毫秒命中缓存** |
| **两端模式共享** | 胶囊孤岛与路径哈希互不相通 | **统一 File ID 缓存池，内存/磁盘模式 100% 共享** |
| **应用退出** | 锁时序混乱、线程池死等，必须 `taskkill` | **原子熔断三步走，0.1 秒秒退** |
| **权限要求** | 尝试引入 MFT/USN 导致必须管理员权限 | **标准 Win32 API，纯净普通权限（`asInvoker`）** |
