### 下一个核心探讨议题：【硬件设备热插拔与盘符监听解耦 (DeviceWatcher)】

#### 1. 现状事实与代码痛点
在重构后的 `MainWindow.cpp` 中，几乎所有业务逻辑和状态都已经被清零，但**底部依然残留着一段 Win32 原生事件拦截代码**：

```cpp
#ifdef Q_OS_WIN
bool MainWindow::nativeEvent(const QByteArray& eventType, void* message, qintptr* result) {
    Q_UNUSED(eventType);
    Q_UNUSED(result);

    MSG* msg = static_cast<MSG*>(message);
    if (msg->message == WM_DEVICECHANGE) {
        // 🚨 违规点：主窗口直接截获 Win32 消息，并将裸指针参数 (wParam, lParam) 传给核心中控
        CoreController::instance().handleDeviceChange(
            static_cast<unsigned long>(msg->wParam), 
            static_cast<unsigned long long>(msg->lParam)
        );
    }
    return false;
}
#endif
```

**问题所在**：
1. `MainWindow` 被迫 `#include <Dbt.h>`、`<windows.h>`，破坏了主窗口的跨平台纯洁性；
2. `CoreController` 作为高层业务中控，居然暴露了 `handleDeviceChange(unsigned long wParam, unsigned long long lParam)` 这种依赖 Win32 裸类型的非标接口；
3. 盘符插拔后，主窗口还要自己写 `onVolumeUnplugged` 槽函数去处理盘符卸载跳转。

---

#### 2. 架构方案探讨：独立的 `DeviceWatcher`（或归入 `VolumeOnlineManager`）应该怎么做？

将硬件消息截获与盘符拓扑感知**彻底下沉为底层的 `DeviceWatcher`（设备监听器）**：

```
                              【硬件设备监听与盘符感知架构】

     [ Windows 原生硬件消息 (WM_DEVICECHANGE) ]
                         │
                         ▼
     ┌─────────────────────────────────────────────────────────────┐
     │       DeviceWatcher / VolumeOnlineManager (底层设备监听中枢) │
     ├─────────────────────────────────────────────────────────────┤
     │ 1. 独立挂载原生事件过滤器 (QAbstractNativeEventFilter)       │
     │ 2. 内部解析 DBT_DEVICEARRIVAL / DBT_DEVICEREMOVECOMPLETE    │
     │ 3. 自动将 Win32 广播解析为标准盘符字符串 (如 "D:", "E:")     │
     │ 4. 维护系统物理在线盘符集合 (QSet<QString> onlineDrives)    │
     └──────────────────────────────┬──────────────────────────────┘
                                    │ (单向向全系统广播标准 Qt 强类型信号)
                                    ▼
       ┌────────────────────────────┼────────────────────────────┐
       │ (driveMounted)             │ (driveUnmounted)           │ (driveUnmounted)
       ▼                            ▼                            ▼
【 DriveBar 盘符栏 】        【 NavigationService 】       【 ContentPanel 】
• 自动点亮新盘符按钮         • 若当前路径处于被拔出的盘符  • 自动更新盘符列表
• 自动移除已拔出盘符           则自动安全退回 computer://  • 刷新驱动器空间
```

---

#### 3. 核心重构收益：

1. **`MainWindow.cpp` 达成“0 行 Win32 原生代码”成就**：
   - 彻底删除 `MainWindow::nativeEvent`，删除 `<Dbt.h>` 等所有 Windows 底层头文件；
2. **`CoreController` 接口彻底跨平台化**：
   - 删除 `handleDeviceChange(wParam, lParam)` 依赖，核心控制器不再接触操作系统原始消息；
3. **盘符拔出时的安全跳转全自动闭环**：
   - 由 `NavigationService` 自行监听 `driveUnmounted` 信号并在拔盘时自动退回 `computer://`，不再需要主窗口写任何胶水代码。
