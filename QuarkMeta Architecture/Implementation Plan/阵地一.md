### 二、 推断：子面板内部的 4 大系统性缺陷（因果链路）

- **[推断 1 - 收藏夹路径未归一化导致“重复收藏与幽灵项”]**
  - **原因**：如果用户通过拖拽将 `C:\Users\Photo` 拖入收藏夹，而另一个操作将 `c:/users/photo` 存入。
  - **影响**：简单的字符串比对判定为“两个不同项目”，导致收藏夹中出现指向同一个物理文件夹的重复项。
  - **结果**：破坏了收藏夹“物理路径绝对唯一性”的大纲红线。
  - **标准解法**：进入 Model 之前强制执行 `QDir::toNativeSeparators(QDir::cleanPath(path)).toLower()` 强归一化。

- **[推断 2 - MetaPanel 多选状态下误触单文件写盘]**
  - **原因**：当用户在内容区框选了 100 个文件时，`MetaPanel` 同时接收到了 100 个路径。
  - **影响**：如果文件名输入框（QLineEdit）或备注框没有及时禁用或切换为“批量模式（显示：100个项目）”。
  - **结果**：用户在文件名框误打一个字符，可能引发对 100 个文件的同名覆盖灾难。
  - **标准解法**：建立明确的 **【单选编辑态】 vs 【多选聚合态】 状态机**，多选时强制禁用单文件特有属性（文件名、尺寸）。

- **[推断 3 - 地址栏面包屑与 NavigationService 缺乏双向绑定]**
  - **原因**：地址栏目前仅作为被动的“路径字符串接收器”。
  - **影响**：当用户在面包屑上点击中间层级（如 `H:\测试\素材\2026` 中的 `素材`）时，地址栏还要通过自定义信号找 MainWindow 转发。
  - **结果**：增加了中转层级。标准做法应直接调用 `NavigationService::instance().navigateTo(subPath)`。

1. **`MetaPanel` 存在极其严重的“双重重复写盘（Double Write）”**：
   - 事实代码 1（`MetaPanel.cpp` 第 562~566 行）：
     ```cpp
     if (fromUser && !m_selectedPaths.isEmpty()) {
         for (const QString& p : m_selectedPaths) {
             MetadataManager::instance().setRating(p.toStdWString(), rating, true); // 👈 第一次写盘！
         }
         emit metadataChanged(rating, m_currentColor);
     }
     ```
   - 事实代码 2（`PanelMediator.cpp` 中监听到该信号）：
     ```cpp
     connect(metaPanel, &MetaPanel::metadataChanged, contentPanel, [contentPanel](int rating, ...) {
         AppCommand cmd;
         cmd.type = AppCommandType::SetRating;
         cmd.params["rating"] = rating;
         CoreEngine::instance().executeCommand(cmd); // 👈 第二次写盘！
     });
     ```
   - **后果**：用户在元数据属性栏每点一次星级或颜色，底层磁盘 `.QuarkMeta.json` 与 SQLite **被连续重复写入了 2 次**！

   在 `AddressBar.cpp`（第 86~92 行）中：

### 二、 推断：现有设计的系统性缺陷（因果链路）

- **[推断 1 - `MetaPanel` 双重写盘导致 I/O 资源浪费与潜在锁竞争]**
  - **原因**：`MetaPanel` 作为纯 UI View 控件，越权直接调用了 `MetadataManager` 写盘，同时又发射了 `metadataChanged` 驱动 `CoreEngine` 再次写盘。
  - **影响**：一次简单的打星打色，底层执行了 2 次文件读取、2 次 JSON 序列化和 2 次全局广播。
  - **结果**：造成 100% 的冗余 I/O 浪费；在机械硬盘或大批量修改时导致明显的界面微卡顿。
  - **标准解法**：**`MetaPanel` 严禁内部直调 `MetadataManager`**，只负责发射变更信号，由 `CoreEngine` / 领域服务单次原子执行。

- **[推断 2 - 地址栏搜刮收藏夹破坏模块自治]**
  - **原因**：地址栏面包屑直接跨窗口寻找 `FavoritePanel` 并直接修改其 Model。
  - **影响**：地址栏与收藏夹面板产生了未受控的强耦合。
  - **结果**：导致模块无法独立测试与重构，一旦收藏夹重构或隐藏，地址栏右键菜单即刻静默失效。
