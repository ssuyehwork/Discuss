【一：窗格树结构】
1. 节点两种：叶子（一个窗格容器）和分割节点（方向 Qt::Horizontal 或 Qt::Vertical，≥2 个子节点，对应一个 QSplitter）。根节点放在现有的窗格宿主区域内。
2. 规范化规则（每次树变化后统一执行一次）：分割节点只剩 1 个子节点时，用该子节点替换自己；子分割节点与父分割节点方向相同时，把子节点并入父节点（展平）。
3. 遍历顺序固定为：深度优先，水平分割从左到右，垂直分割从上到下。标签页名称、合并、拆分、导出路径列表都使用这个顺序，只在一处实现。
4. 主窗格（m_panel）仍然是树中的一个叶子，可以被移动，也可以位于任意位置；副窗格仍然通过 m_rootPane 指回主窗格。
5. ContentPanel::paneCount、panes、isSplitMode 对副窗格仍返回整个窗格组的值；panes() 仍是扁平列表，不得因树结构而递归。

【二：落点判定与高亮（唯一一处）】
1. 新增唯一的判定函数：输入鼠标位置，找出鼠标下方的目标窗格，并在该窗格内判定落在 上/下/左/右 哪一侧，输出：目标窗格、方位、是否有效、高亮矩形（该窗格对应一半区域，坐标转换到窗格组宿主控件坐标系）。
2. 区域规则：沿用现有 25% / 75% 阈值，先判左右、再判上下；窗格中心区域无效。
3. 高亮：蓝色半透明（沿用现有样式），范围就是松开后新窗格占据的区域。
4. 落点生效规则：在目标窗格 T 的某一侧放入窗格 N：
   - 左/右 → 水平；上/下 → 垂直。
   - 若 T 的父分割节点方向与之相同，则 N 作为同级兄弟插入 T 的前面或后面；
   - 否则用一个新的分割节点替换 T，子节点为 [N, T]（左/上）或 [T, N]（右/下）。
5. 窗格不能落在自己身上；落在自己所在位置的相邻无意义位置（结果布局与原布局相同）时，视为无效，不高亮。
6. 最小尺寸校验：按树逐层计算最小宽高（水平节点：宽=子节点最小宽之和+分隔条，高=子节点最小高的最大值；垂直节点反之）。落点生效后若宿主区域放不下，该落点判定为无效，释放时用 ToolTipOverlay::instance()->showText(QCursor::pos(), "空间不足，无法放置到此处", 2000, QColor("#e81123")) 提示，不改变布局。
7. 窗格数已达 kMaxPanes 时：标签页拖入保持现有行为；窗格移动不受影响（数量不变）。

【三：按住窗格标题栏拖动窗格】
1. 在窗格组为多窗格时（isSplitMode），在标题栏空白区域或标题文字区按住左键拖动，超过 QApplication::startDragDistance() 开始拖动；单窗格时不响应。标题栏按钮（分屏、隐藏项、递归）点击不受影响，拖动不能从按钮上触发。
2. 实现为 QDrag，使用独立 mime 类型（例如 application/x-quarkmeta-panemove，携带被拖窗格标识），与标签页拖入共用 ContentPanel 的 dragEnter/dragMove/drop 路径和第二节的判定函数。拖动缩略图使用窗格标题栏抓图，热点为按下点并限制在图片范围内。
3. 松开后：从树中取出该窗格，按第二节规则放到目标侧，规范化，重新布局。窗格内部状态（当前目录、视图模式、选区、排序、过滤、缩放）完全保留，不重新创建 ContentPanel，只移动其宿主容器。
4. 取出窗格后若原父节点只剩一个子节点，按规范化规则合并。
5. 任何窗格（主窗格或副窗格）的标题栏都能发起拖动。
6. 取消现有的"拖标题栏切换水平/垂直"功能及其信号与预览代码（orientationToggleRequested 等），因为它与窗格拖动使用同一手势；相关的 splitOrientation() 查询与 setSplitOrientation 若不再有调用方，一并删除。删除前先核实无其他依赖。

【四：标签页拖入】
1. 标签页拖到某个窗格上，用同一判定函数，新窗格落在该窗格的某一侧，规则同第二节。不再以整个窗格组作为判定区域。
2. 中心区域无效时，光标显示禁止，释放无任何变化。

【六：尺寸分配】
