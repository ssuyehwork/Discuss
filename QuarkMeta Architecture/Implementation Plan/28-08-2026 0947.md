### 核心探讨议题：【应用生命周期与优雅退出清场体系 (Lifecycle & Shutdown)】

#### 1. 现状事实与致命隐患
回顾我们在最初审核 `TrayController.cpp` 时发现的严重问题：
```cpp
void TrayController::onQuitApp() {
    if (m_trayIcon) m_trayIcon->hide();
    if (m_mainWindow) m_mainWindow->close();
    // 🚨 隐患代码：直接强退主事件循环！
    QApplication::exit(0);
}
```

**为什么直接 `exit(0)` 存在严重隐患？**
1. **后台并发线程来不及收尾（Hard Abort 崩溃）**：
   当用户点击退出时，后台可能有子线程正在向 `.QuarkMeta.json` 或 SQLite 写入数据。强杀事件循环可能导致后台线程在执行一半时发生**文件写入截断（数据损坏）或 SQLite WAL 日志未合并锁死**；
2. **临时解密文件残留泄密风险**：
   如果此时有用户正在预览受外壳保护的 `.amenc` 临时文件，强杀进程会导致 `DecryptedFileHandle` 析构被跳过，解密后的明文临时文件可能**残留在 Windows 临时目录中**；
3. **主窗口 `closeEvent` 配置未落盘**：
   如果子系统在 `closeEvent` 还没来得及 `AppConfig::sync()`，配置直接丢失。

---

#### 2. 架构方案探讨：标准的“优雅退出四阶段清场流水线”

系统必须建立一个统一受控的 **`AppLifecycleManager`（或在 `CoreController` 中闭环）**，将退出流程分为严密的 4 个阶段：

```
                              【优雅退出四阶段清场流水线】

   [ 退出触发源 (Tray 退出 / 菜单退出 / 系统关机 WM_QUERYENDSESSION) ]
                               │
                               ▼
   ┌─────────────────────────────────────────────────────────────────────────────┐
   │ 阶段 1: 信号阻断与防重入 (Phase 1: Ingress Lock & Signal Mute)              │
   │ • 标记 s_isShuttingDown = true                                              │
   │ • 立即隐藏系统托盘图标 (m_trayIcon->hide())，防止用户连续双击退出造成重入    │
   │ • 关闭所有子对话框与预览窗口 (QuickLook, Dialogs)                            │
   └───────────────────────────┬─────────────────────────────────────────────────┘
                               │
                               ▼
   ┌─────────────────────────────────────────────────────────────────────────────┐
   │ 阶段 2: 任务硬熔断与线程等待 (Phase 2: Worker Pool Abort & Join)            │
   │ • ThumbnailPipelineService::cancelAll() 瞬间丢弃所有提图任务                │
   │ • PhysicalDiskSearchExtractor 标记 abortFlag = true 停止深搜                │
   │ • 等待核心写盘作业完成 (超时保底 1.5 秒，绝不无限卡死)                       │
   └───────────────────────────┬─────────────────────────────────────────────────┘
                               │
                               ▼
   ┌─────────────────────────────────────────────────────────────────────────────┐
   │ 阶段 3: 状态落盘与垃圾清理 (Phase 3: State Flush & Scratch Sweep)           │
   │ • PanelLayoutManager::saveLayoutState() 确保五栏尺寸存盘                    │
   │ • AppConfig::instance().sync() 物理固化配置                                 │
   │ • 自动清理临时解密目录 (amtemp) 与过期缩略图缓存                             │
   └───────────────────────────┬─────────────────────────────────────────────────┘
                               │
                               ▼
   ┌─────────────────────────────────────────────────────────────────────────────┐
   │ 阶段 4: 数据库安全下线与退出 (Phase 4: SQLite Checkpoint & Clean Exit)      │
   │ • DatabaseManager 执行 WAL Checkpoint (确保所有日志合流落盘)                 │
   │ • 关闭所有数据库连接                                                        │
   │ • 安全调用 QCoreApplication::quit() 优雅结束主线程循环                      │
   └─────────────────────────────────────────────────────────────────────────────┘
```

---

#### 3. 核心重构收益：
1. **彻底根治数据库损坏与 WAL 锁死**：保证退出前所有事务安全 Commit 与 Checkpoint；
2. **彻底消灭数据半途丢失**：确保配置文件与元数据 100% 优雅落盘；
3. **零隐私残留**：临时解密文件与临时缓存百分之百安全焚毁。
