### 一、 事实：当前对话框与悬浮遮罩的体系现状

在系统交互中，存在以下 4 大核心对话框与 3 个全局悬浮遮罩：

1. **业务核心对话框**：
   - `TagManagerDialog`（标签词库管理面板）：负责树形分组、标签词条管理、调色板绑定；
   - `DuplicateConflictDialog`（重复文件冲突排重对话框）：负责展示三阶哈希检测出的冲突组，提供“保留最新/保留最大/批量勾选粉碎”；
   - `BatchCreateDialog`（批量新建项目对话框）：负责基于模板规则批量生成文件夹、Markdown 或文本文件。
2. **通用无边框基类族（FramelessDialog 体系）**：
   - `FramelessDialogBase` / `FramelessDialog` / `FramelessMessageBox` / `FramelessInputDialog` / `FramelessColorPicker`。
3. **三大全局单例悬浮遮罩（Overlays）**：
   - `ToolTipOverlay`：全局矢量高质感气泡提示（彻底取代 Qt 原生低分辨率 ToolTip）；
   - `UndoToastOverlay`：底部 7 秒（7000ms）操作反馈与撤销栏；
   - `TagSelectorOverlay`：输入标签时的悬浮候选词联想面板。

---

### 二、 推断：现有设计的 3 大架构隐患（因果链路）

- **[推断 1 - 对话框内部自立山头，未完全对接已落地的领域服务]**
  - **原因**：历史遗留代码中，`TagManagerDialog` 内部还留存着零散的直接 SQL 操作；`DuplicateConflictDialog` 内部可能还在私自删除文件。
  - **影响**：这些对话框游离在 `TagLexiconService` 与 `PermanentDeleteService` 的统一防护管道之外。
  - **结果**：极易产生“在主界面删除有撤销/加锁，在排重对话框删除却漏掉清理撤销栈”的行为不一致 Bug。
  - **标准解法**：**所有对话框 100% 退化为纯 View**，排重粉碎必须调用 `PermanentDeleteService`，词库编辑必须调用 `TagLexiconService`。

- **[推断 2 - 无边框对话框外壳未接入 `FramelessWindowHelper`]**
  - **原因**：各个 Dialog 内部各自重写了一套私有的标题栏拖拽或鼠标按下移动代码。
  - **影响**：对话框在高 DPI 缩放、边缘吸附与移动平滑度上与主窗口存在体验差异。
  - **结果**：造成窗口交互体验的割裂。

- **[推断 3 - 悬浮遮罩（Overlay）越界截获全局事件]**
  - **原因**：`TagSelectorOverlay` 与 `ToolTipOverlay` 在计算屏幕物理坐标（`QCursor::pos()`）时，若未对多显示器（Multi-Monitor）跨屏边缘做严密的几何碰撞检测。
  - **影响**：在屏幕边缘弹出气泡或下拉框时，容易发生弹窗被切掉一半或飘到副屏之外的显示 Bug。

                         【对话框与悬浮遮罩标准架构】

    • ToolTipOverlay / TagSelectorOverlay 引入智能多屏碰撞自适应 (防越界出屏)
