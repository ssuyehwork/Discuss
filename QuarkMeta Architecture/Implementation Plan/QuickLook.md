### 一、 事实：QuickLook 子系统的现有交互与业务现状

`QuickLook` 是 QuarkMeta 最核心的视觉交互载体，其业务链路包含以下 4 个关键环节：

1. **主视口与鹰眼小地图（GraphicsView & Minimap）的双向联动**：
   - 主视口（`QuickLookGraphicsView`）：支持鼠标滚轮平滑缩放、中键/左键抓手拖拽平移（Pan）、双击在“自适应窗口（Fit View）”与“1:1 原始像素（100% View）”之间快速切换；
   - 鹰眼小地图（`QuickLookMinimap`）：位于右下角的半透明全局缩略图，绘制红色视口指示框；用户在小地图上拖动红框时，主视口实时同步平移。
2. **键盘流式连续切图与资产标注**：
   - 按 `Space` / `Esc`：关闭预览；
   - 按 `Left` / `Right` 方向键：前后相邻文件毫秒级轮播切图；
   - 按 `0 ~ 5`：直接修改当前预览文件的星级；
   - 按 `Alt + 1 ~ 9`：直接修改当前预览文件的颜色标记；
   - 按 `Delete`：直接触发当前预览文件的移入回收站。
3. **多格式内容多态呈现**：
   - 图像/矢量图（JPG, PNG, WEBP, GIF, SVG, PSD, AI 等）；
   - 纯文本/代码/Markdown（TXT, MD, CPP, H, JSON, XML, LOG 等）；
   - 外壳加密文件（`.amenc` 临时 RAII 解密预览）。

### 二、 推断：现有设计存在的 3 大核心架构缺陷（因果链路）

- **[推断 1 - 小地图与主视口双向同步的“递归震荡与抖动”]**
  - **原因**：主视口平移会发射 `viewportChanged` 信号驱动小地图更新红框；而用户在小地图拖动红框时又发射 `visibleRectChanged` 驱动主视口移动。
  - **影响**：如果缺乏严格的防重入状态锁（`m_isUpdatingViewport`），双向信号会在浮点数像素四舍五入时产生相互反弹。
  - **结果**：导致在大图缩放或拖拽边缘时，小地图红框发生肉眼可见的高频微颤与抖动（Jitter）。

- **[推断 2 - 超大分辨率图像（4K/8K/巨型长图）的主线程解码阻塞]**
  - **原因**：当切到一张几十 MB 或 8000×8000 像素的巨型大图时，如果在主 UI 线程直接调用 `QPixmap::load()`。
  - **影响**：图像解码会霸占主线程 200~500 毫秒，期间窗口无法响应键盘事件。
  - **结果**：导致用户快速按方向键切图时出现明显的卡顿与掉帧。
  - **标准解法**：主视口必须采用“后台异步解码 -> 先展视低分辨率占位图 -> 高清位图平滑淡入替换”的渐进式渲染机制。

- **[推断 3 - 预览窗口内部多格式渲染代码严重违背单一职责]**
  - **原因**：图片缩放绘制、文本语法高亮渲染、Markdown 解析全部堆叠在 `QuickLookWindow.cpp` 单个文件中。
  - **影响**：导致 `QuickLookWindow` 膨胀为 800+ 行的多媒体杂物类，新增格式（如 PDF 预览或音频波形预览）时必须大幅修改窗口核心代码。
  - **结果**：扩展性差，难以维护。

### 二、 推断：现有设计的 3 大系统性缺陷（因果链路）

- **[推断 1 - 全局顶层控件搜刮破坏封装且存在偶发崩溃风险]**
  - **原因**：预览窗口作为独立的 Tool 窗口，不应跨窗口去反查主界面的内部私有控件 `FavoritePanel`。
  - **影响**：如果主窗口处于最小化、销毁中或重构了面板层级，`findChild` 会产生无谓的遍历开销，甚至在多窗口生命周期切换时访问失效指针。
  - **结果**：破坏了模块独立性。正确做法应通过信号或领域服务直接判定与执行收藏。

- **[推断 2 - 快速切图导致后台线程池排队雪崩与 CPU 暴涨]**
  - **原因**：`renderImage` 缺少类似 `ThumbnailPipelineService` 的代际锁（Generation ID）。
  - **影响**：当用户在 4K/RAW/PSD 等大图目录下快速按方向键切图时，线程池里积压了大量“用户已经跳过不看”的无用解码任务。
  - **结果**：导致真正想要看的那一张新图片排在队列末尾迟迟出不来（界面卡在“正在加载预览...”达数秒），CPU 占用率短时间内飙升至 100%。

- **[推断 3 - 鹰眼小地图在超大图与极小视口下的边界保护需加固]**
  - **原因**：在 `QuickLookMinimap::handleMouseInteraction` 中，鼠标点击计算的中心点未对小地图自身的内边距（Padding）做严密防护。
  - **影响**：在极端缩放比例（10.0x 放大）下，小地图红框会发生微小的浮点四舍五入抖动。
